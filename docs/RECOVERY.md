# Original checkout recovery

Before editing, all original files including `.git` and `build/` were archived in `recovery/original_project.zip`. `recovery/audit.json` records original SHA-256 values and per-file restoration status. Nine files were recovered from SHA-1-verified HEAD blobs; 49 tracked non-build files could not be recovered from their HEAD copies. The original specification, most DSP/app code, documentation and MATLAB script were unreadable random binary bytes rather than text. Original PNG signatures were also invalid. Inspection found 93 decompressible loose Git objects and 81 corrupt ones; the Git index signature was invalid.

Readable CMake/script/configuration files and recovered CONTRIBUTING guidance established the intended architecture. It already included a shared C++ core, Windows WASAPI backend, Android app, MATLAB visualizer, simulator, calibration tool, tests and documents. Reconstruction retained those entrypoints and directories. The detailed original specification could not be read or recovered; the replacement specification describes the implemented scope rather than pretending to reproduce lost prose.

The original `.git` is intentionally unchanged. No reset, index replacement, commits or history rewrite were used. Generated builds go to `build_verified/`; original `build/` is preserved. The old example JSON calibration and all-zero diagnostics are archived separately, because they are not evidence for physical acoustic attenuation. New results live exclusively in `results/` and are generated by executable simulations.

Do not overwrite this backup while experimenting with history repair. A clean repository can be initialized from the finished files in a separate directory if desired; that is outside this reconstruction.
